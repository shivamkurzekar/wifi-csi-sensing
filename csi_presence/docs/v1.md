# csi_presence — v1: room presence detection from WiFi CSI

**Target:** ESP32-S3, ESP-IDF v5.4
**Status:** flashed and validated on real hardware (2026-08-16) — see §
"What testing on real hardware found" below. Not yet tested against an
actual occupied-vs-empty-room comparison (nobody was in the room during
validation, so only the "stays quiet when empty" half is confirmed).
**Relationship to `csi_test`:** a separate, standalone project. Reuses two
pieces of proven infrastructure from there (see below) but shares no files
and was built without modifying it.

---

## What this is

`csi_test` answers "what does WiFi CSI look like." This project answers a
narrower question: **is there a person in the room, right now, yes or no.**

It streams a live `PRESENCE,...` line over serial on every processed packet
with a motion-energy score and a boolean presence flag — no offline
analysis step required.

## Where the algorithm came from

The core idea — variance of one subcarrier's phase, over time, as a motion
signal, with a self-calibrating ambient baseline and hysteresis to avoid
flicker — is adapted from the *approach* used in
[`ruvnet/RuView`](https://github.com/ruvnet/RuView)'s
`firmware/esp32-csi-node/main/edge_processing.c` (MIT licensed). That
project has real, documented credibility baggage (see its own `PROOF.md`
and the public "AI slop" controversy around it) — but this specific piece
of code was verified by reading it directly, and it's a genuinely sound,
standard signal-processing technique independent of anything else in that
project. Nothing was copied verbatim; this is a fresh implementation, with
one deliberate change from the source approach (below).

## Why this is a better signal than what `csi_test`'s report computes

`csi_test`'s "variability" metric is the spread of amplitude **across all
subcarriers within one packet** — a spatial snapshot. A room that's simply
furniture-dense and RF-complex can score "high variability" even with
nobody moving, because the metric never looks at *time*.

This project's "motion energy" is the variance of **one subcarrier's phase
over the last ~1 second** — it only responds to the channel actually
*changing*, which is what motion causes (new multipath, signal blocked/
unblocked) and a static-but-complex room does not.

## Algorithm

1. **Extract + unwrap phase** for every subcarrier, every packet. Unwrapping
   matters: raw `atan2` wraps at ±π, so a real ~3.2 rad phase change would
   otherwise look like a fake jump from +3.1 to -3.1. (`csi_test` does not
   do this — a gap noted in its own docs.)
2. **Pick the noisiest subcarrier once**, after a short (20-frame) warmup,
   via a running (Welford) variance tracker across all subcarriers — then
   keep that pick for the rest of the session. (v1 originally re-picked
   periodically; real-hardware testing found that actively harmful — see
   below.)
3. **Track only that subcarrier's phase** into a ring buffer.
4. **Motion energy** = variance of the last 20 samples in that buffer.
5. **Adaptive calibration**: watch ambient motion energy with the room
   (presumed) empty, then set `threshold = ambient_mean + 3 × ambient_stddev`.
6. **Hysteresis + debounce** (a Schmitt trigger): enter "present" the
   instant the score crosses the threshold; only clear "present" after 5
   consecutive frames below half the threshold, so a score dithering near
   the boundary doesn't flicker the flag.

## Deliberate changes from the source approach

- **Time-based calibration, not frame-count-based.** RuView calibrates
  over a fixed frame count (1,200 frames), implicitly assuming a steady
  ~20 Hz capture rate. Our own earlier capture on this exact network
  showed wildly irregular inter-packet gaps (0.2s to 2.6s, depending on
  ambient traffic) — so a frame-count window would take an unpredictable
  amount of wall-clock time, or worse, calibrate against a burst of only a
  few seconds' worth of samples. This project calibrates over a fixed 60
  seconds of wall-clock time instead (`CALIB_SECONDS`), regardless of how
  many packets arrived in that window. If too few samples arrive
  (`CALIB_MIN_SAMPLES`), it keeps waiting rather than committing to a
  threshold estimated from noise.
- **Pick the subcarrier once, not periodically.** This wasn't originally a
  deliberate change — it started as a straight port of RuView's periodic
  reselection, and turned into a deliberate deviation only after real
  hardware testing showed it corrupting calibration (see below).

## What testing on real hardware found

The algorithm as first written was broken in three ways that a build (or a
read of the code) would not have caught — all three only showed up by
actually flashing it and watching the serial output:

1. **Stuck on a dead subcarrier.** `s_primary_subcarrier` defaulted to
   index 0 and only got its first real pick after a full
   `TOPK_REEVAL_FRAMES` (100) window. At this network's real, sparse
   packet rate that took well over a minute — during which index 0 (a
   near-zero-amplitude edge subcarrier, confirmed from `csi_test`'s
   original capture) fed a flat, zero-variance phase into "motion energy."
   It would never have detected motion, ever, no matter what happened in
   the room. **Fix:** a short 20-frame warmup does the first pick quickly.
2. **Periodic reselection corrupted calibration.** The original design
   re-picked the noisiest subcarrier every 100 frames to "track recent
   conditions." But the calibration accumulator sums `motion_energy`
   across the whole 60s window regardless of which subcarrier produced
   it — so a mid-calibration reselection silently mixed two unrelated
   subcarriers' noise levels into one meaningless average. **Fix:** pick
   once, keep it for the session (see algorithm step 2 above).
3. **A fake motion spike at the subcarrier switch, and a stale presence
   latch.** Locking onto the new subcarrier left the phase ring buffer
   full of the *old* (index-0) subcarrier's readings; the first
   post-lock variance calculation mixed old and new subcarrier phase,
   producing a discontinuity spike that isn't real motion. That spike got
   baked into the calibration average and inflated the learned threshold
   to ~4× the real steady-state range (65 vs. an actual 4–18) in one test
   run. Separately, `presence_detected` could latch `true` during the
   pre-calibration window (which uses a crude always-trips
   `PRESENCE_DEFAULT_THRESH`), then take `PRESENCE_CLEAR_FRAMES` frames to
   debounce back off after the real threshold applied. **Fix:** clear the
   ring buffer at the moment of lock-in, start the calibration clock there
   too (not at boot), and reset the presence flag when calibration
   completes.

After all three fixes: locked onto a real subcarrier within the first ~20
frames, calibrated to a threshold (44.98) sitting sensibly above the
observed steady-state motion energy (6.5–14.4), and `present` read `0`
correctly and immediately from the first post-calibration frame, with no
one near the device. That's the "stays quiet in an empty room" half of the
claim, verified. The "correctly flips to `1` when someone actually walks
in" half has not been tested yet — that requires a human physically
present during a run, which wasn't available during this validation pass.

## Known limitations (v1)

- **Mixed packet shapes.** Like `csi_test`, some received packets carry
  fewer subcarriers than others (e.g. non-HT frames vs. HT frames — see
  `csi_test/docs/v1.md` §6). When the subcarrier count changes between
  packets, phase-unwrap continuity is deliberately dropped for that one
  frame rather than unwrapping across a discontinuity that isn't real
  motion. This causes a one-frame gap in the phase history whenever packet
  type switches.
- **Heuristic, not validated accuracy.** Same caveat RuView's own docs
  carry: this is a threshold-crossing heuristic, not something with a
  measured false-positive/false-negative rate. Strong RF interference can
  plausibly trigger false positives.
- **Single subcarrier.** Only the single noisiest subcarrier feeds the
  motion score; a person standing very still in a spot that happens to
  barely perturb that one subcarrier could be missed even while other
  subcarriers show more signal. A future version could combine top-K
  subcarriers instead of just the top-1.
- **`WIFI_SSID` / `WIFI_PASSWORD`** live in `main/wifi_credentials.h`
  (gitignored) — same pattern as `csi_test`, see its
  `main/wifi_credentials.h.example`.

## How to test it

```bash
cd projects/csi_presence
source ~/Projects/esp/esp-idf/export.sh
idf.py -p /dev/ttyACM0 flash monitor
```

Keep the room empty for the first 60 seconds (calibration window — the boot
log says so). After that, watch the last column of each `PRESENCE,...` line
flip to `1` when someone walks in.

```
PRESENCE,<timestamp_us>,<rssi>,<primary_subcarrier_idx>,<motion_energy>,<threshold>,<calibrated>,<present>
```
